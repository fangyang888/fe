# 图书馆 RAG 服务上线计划

## 产品目标与当前假设

面向读者提供图书馆业务规则问答：输入自然语言问题，返回简明答案、可点击的原文来源；资料没有依据时明确说明无法确认。首版只使用**经业务方确认可公开的资料**。管理员通过受控的导入命令更新知识库，读者通过网页或 API 提问。

你已有服务器或容器环境。首版按容器部署设计，具体入口域名、模型服务和实际文档来源在接入时配置。当前 `corpus/` 是虚构资料，只用于开发、演示和回归检查；上线前替换为真实资料，并由业务方确认答案和来源。

## 首版范围

```text
经审核的业务资料 ─→ 导入任务 ─→ 解析 / 清洗 / 切分 ─→ Embedding ─→ Qdrant
                                                        ↓
读者网页 ─→ 问答 API ─→ 检索 ─→ 证据检查 ─→ LLM 生成 ─→ 答案 + 原文引用
```

技术基线：Python + LlamaIndex 处理导入、索引和查询；Qdrant 作为可持久化向量库；轻量 HTTP API 和网页作为产品入口；Docker Compose 作为第一版服务器部署描述。模型供应商通过配置接入，选型时同时确认中文 embedding、生成模型、费用和数据处理要求。具体包版本在实施时锁定。

[LlamaIndex 的 Ingestion 文档](https://developers.llamaindex.ai/python/framework/understanding/rag/loading/)覆盖 Reader、Document、切分及 metadata；[Ingestion Pipeline](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/)用于组织导入步骤；[QdrantVectorStore](https://developers.llamaindex.ai/python/framework-api-reference/storage/vector_store/qdrant/)可承载检索索引；[Querying](https://developers.llamaindex.ai/python/framework/understanding/rag/querying/)把检索、后处理和生成分开。这里的技术基线是本项目的实施选择，后续按实测结果调整。

## 数据与接口约定

- 每份原始资料保留 `source_id`、标题、原文位置或 URL、更新时间、版本和公开范围。每个片段带回原始资料标识，回答引用应指向原文，而非仅显示向量库内部 ID。
- 导入任务维护稳定文档 ID 和内容校验值，识别新增、修改与删除；记录失败文件并允许重试。发布新版索引时先在独立版本完成构建和验证，再切换查询入口并保留上一版供回滚，避免读者在更新中看到半成品或已删除资料。
- `POST /v1/ask` 输入 `question`；输出 `answer`、`status`（`answered` / `insufficient_evidence` / `error`）、`citations`（标题、原文链接、引用片段）和 `request_id`。`GET /healthz` 检查进程存活，`GET /readyz` 检查模型和检索依赖是否就绪。
- 首版只检索公开资料。若以后纳入内部资料，先加入身份与文档级权限过滤，再让它进入相应读者的检索范围。

## 上线门槛

现有 `eval/` 的 20 道题只做开发回归。真实资料到位后，至少整理一批由馆方确认的真实问题，并覆盖重点规则、跨文档问题和无答案问题。先测出基线，再与业务方确定检索命中、答案正确、引用支持、拒答和响应时间的门槛；所有关键规则错误都要逐题处理。上线前至少完成以下演练：

1. **资料生命周期：** 新增、更新、删除、重复导入和索引回滚。
2. **服务可靠性：** 容器重启、向量库或模型服务短暂不可用、超时和恢复。
3. **数据保护：** 密钥不进仓库和镜像；管理导入入口受控；日志避免记录敏感原文或完整个人问题。
4. **业务核对：** 来源链接可访问、引用片段确实支持答案、过期规定不再被回答。

## 现在要做的第一段工作

先实施 M1。代码建议放在 `projects/rag_learning/app/`，与现有 `exercises/` 分开；`corpus/` 暂作示例输入。第一轮按“导入命令 → Qdrant 检索 → 问答 API → 最小网页 → 容器启动与重启验证”的顺序完成。每加一层都用 Q01、Q06、Q18 检查来源和拒答，随后扩到 20 道题。

接入真实馆方资料时，需要补齐资料来源、格式、更新频率、可公开范围、原文链接和业务负责人。这些信息决定解析方式、发布流程与上线验收；在资料到位前，M1 仍可独立完成。

基础服务稳定之后再评估混合检索、重排序或 Agent 流程；每项改动都用固定题集对照效果、延迟和成本。
