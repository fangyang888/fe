# 意图路由与确定性业务

## 为什么要分流

商品价格、库存等已有可靠数据库逻辑时，不需要让通用Agent自由决定所有细节。模型负责理解语言，确定性Service负责查询和业务规则。

计划路径：

```text
消息 → 结构化意图
  ├─ 商品类 → ProductCustomerService → Repository → MySQL
  └─ 通用类 → LangChain Agent → 通用Tools
```

## 路由原则

- 同一能力只保留一个权威入口。
- 路由结果可测试。
- Service校验实体完整性。
- 查询结果为空和依赖异常要区分。
- 回答中的价格库存来自数据库，不来自模型记忆。

## 验收

准备一组固定问题，证明商品意图、通用问题和字段补全分别进入正确路径。
