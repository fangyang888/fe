# 多轮上下文与上下文工程

## 多轮不只是保存全部消息

上下文需要选择：近期原始消息、业务状态、历史摘要、用户明确资料和工具结果。无限追加会增加成本、延迟并降低相关性。

## 策略

- 使用conversationId隔离会话。
- 保留最近必要消息。
- 长会话做摘要，但关键业务事实从数据库重新读取。
- 工具大结果只保留摘要或引用。
- 用户切换任务时更新pendingIntent。
- 敏感信息按最小需要进入模型。

## 练习

构造“先问手机、补预算、再切换到查订单”的多轮用例，验证旧的商品字段不会污染订单意图。

## 验收

能解释MySQL历史、Redis业务状态、LangGraph State和模型Prompt各自保存什么。
