# Nginx路由、灰度和回滚

## 目标路由

```text
/api/agent/* → Python :8000
/api/*       → NestJS :3000
```

SSE代理需要关闭不合适的缓冲、设置合理超时并保持连接。超时不能无限增大，根本问题仍要由应用层超时和取消解决。

## 灰度

按用户、会话或稳定哈希分流，确保同一conversation尽量落到同一实现。建议5%、20%、50%、100%，每阶段观察错误率和延迟。

## 回滚

回滚只切换路由，不依赖重新构建；数据库Schema必须在灰度期间兼容新旧两版；提前演练并记录负责人和触发阈值。

## 验收

在测试环境执行切换和回滚，正在进行的旧SSE连接不被粗暴破坏，新请求按预期进入目标服务。
