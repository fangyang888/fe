# 小数价格与个人资料发布说明

金额接口的单位仍然是元，例如 `9.9`；数据库使用 `DECIMAL(12,2)`，计算和微信支付转换为整数分。现有整数价格的数值不变。

发布顺序：

1. 备份正式库的 `product`、`order`、`order_item` 表，并保留旧服务版本。安排停止商品编辑、下单与支付请求的短暂维护窗口。
2. 在目标数据库执行同目录 `20260928-decimal-prices.sql`。确认四个金额字段均为 `decimal(12,2)`，抽查旧价格和历史订单数值未变。MySQL DDL 自动提交，脚本可重复执行。
3. 部署后端与管理后台，再发布 `miniapp/dist` 小程序产物。不要仅发布小程序：旧后端/整数列不能正确保存小数价格。
4. 验证创建价格 9.90 的测试商品、购物车数量 3 合计 29.70、订单金额 29.70、模拟支付请求金额 2970 分。测试环境可以执行；正式支付需要单独做受控验收。
5. 在微信公众平台核对手机号能力、隐私声明，以及 `request`、`uploadFile` 合法域名 `https://fzmall.xyz`。服务器需配置 `WX_APPID`、`WX_SECRET`、`PUBLIC_BASE_URL`，并确保图片目录可写且持久化。
6. 真机验证“我的 → 个人资料与手机号”：头像上传、修改昵称和性别、同意/取消手机号授权、保存并重新进入；退出后重启仍保持未登录，点击登录可恢复。

本次没有执行正式库升级或上线。若需要回退，优先修复服务代码并保留小数列；不要直接改回 INT，已经产生的小数金额会丢失。恢复备份前须处理发布后的新增订单数据。
