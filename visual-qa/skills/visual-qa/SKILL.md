# Visual QA

## 定位插件与项目

插件根目录是本文件所在目录的 `../..`。从当前实际 SKILL.md 路径解析根目录，不硬编码作者机器路径；目标项目与插件根目录是两个不同目录。

先读取目标项目适用的 AGENTS.md、页面创建规范和构建配置。保持用户指定的框架、页面位置和禁止读取的文件范围，不初始化替代项目。只做验收时不自动重写页面。

## 快速生成路径

- 合并读取必要规范、目标入口和运行配置；其中必须提取目标项目明确声明的 CSS 长度单位策略。项目要求局部固定尺寸使用 rem 时，在 Web case 中设置 `cssRules.preferRem: true`；项目未声明时保持关闭，不自行假设。只检索用户允许的共享组件。业务预览与 QA 的 Node 版本分别核对，不通过失败构建试探版本。不要为单页运行全仓扫描、类型检查或有上传副作用的构建。
- 用户已明确授权实现且范围清楚时，简要说明方案后继续，不额外增加确认轮；用户要求先给方案或目标项目规范明确要求确认时遵从。关键图片边界或业务范围有歧义时先澄清。
- 设计树、生成代码参考和基准截图各按需获取并保存，同一设计未变化不重复读取；只补缺失字段，禁止输出完整树或批量下载生成碎片。已确定的独立图片可并行导出。
- 首版可运行后立即执行 adaptive，直接交付其生成的 comparison.html 作为首版对比；先看摘要，失败时一次处理所有局部裁片，多组样式假设用 variants。首版对比不等于最终验收。
- 单页迭代不需要代码版本缓存或用户禁止读取其它页面时，verify 使用 `--skip-code-scan`：跳过全仓 Git/文件指纹扫描，同时禁用验收结果缓存，每轮仍截图；它不跳过图片、字体、结构、CSS 和 final 校验。不要与 changed-only / reuse-verification 组合。
- 复用未变化的设计与素材、开发服务和浏览器；无需重新编写截图、比较图或计时脚本。报告已有分阶段 timings，区分首版耗时、最终验收耗时和单次 CLI 耗时，不把单次命令提速当成整页提速承诺。

CLI 源码、锁文件和用例随插件携带，不提供 MCP Server。执行 `node "<插件根目录>/scripts/run.mjs" help` 检查 CLI。需要初始化时，在插件根目录运行 `npm ci` 和 `npm run build`；需要 Node.js 18+。不要在业务项目安装插件依赖。缺少运行时、依赖或写权限时明确说明限制，遵守环境授权，不宣称验收通过。

首次接入、切换机器或遇到浏览器、设计图、输出目录、Harmony 设备问题时，先运行 `doctor`；它只做环境和用例预检，不执行页面验收。多个页面或多平台回归使用 `suite`，读取 suite JSON 并生成汇总 JSON、JUnit 与自包含 HTML 看板；批量结果不能替代各 case 的原始报告。

命令从目标项目目录运行，case、截图、缓存和报告使用明确的项目输出路径；不要把业务数据写进插件目录。CLI 详细参数见 [README](../../README.md)，按需阅读。

## 平台选择

用户要求 Web SCSS 变量抽取或样式重构且保持外观不变时，读取 [SCSS 重构验收](references/scss-refactor.md)，使用修改前的真实页面作为基准，无需额外设计稿。该流程替代下面的设计读取和 Web 页面实现流程；不适用于 ArkUI 原生样式。纯样式变量替换无需搜索或更换组件。

用户明确指定的平台优先。用例 `platform` 缺省为 `web`；原生 ArkUI 使用 `harmony`。根据目标模块的 `module.json5`、ArkTS `.ets` 页面及构建配置确认原生项目；混合工程以当前页面为准，Web 组件内的 H5 不按原生组件处理。

- Web 页面读取 [Web 实现与验收](references/web.md)。
- Harmony 原生页面读取 [Harmony 实现与验收](references/harmony.md)。该模式仅做截图视觉验收，不能声称 DOM/CSS 或原生组件测量通过。
- 共用下面的设计与素材流程。不为原生项目创建替代 H5 页面。不要自动发布或安装其它插件。

## 读取设计与图片意图

- 有 Pixso URL 时，先把用户指定的图片 item-id 与红框写入 intent 配置，并执行 `intent-plan --strict`。用户指定的图片身份优先于 Pixso 的 GROUP/FRAME/TEXT 等类型。**在首次 design_to_code 和业务代码编写前**，读取并执行 [生成前图片边界检查](references/generation-context.md)；不要等页面渲染或 visual diff 才纠正图片实现。
- Pixso MCP 不可用时，可使用用户已提供的参考图继续；没有可用视觉依据时只说明缺失内容，不猜测设计，也不伪造验收基准。
- `single-image` 是不透明边界：对应 Pixso 节点只允许调用 `get_export_image`，禁止对它调用 `design_to_code`、`get_node_dsl` 或 `query_nodes`，也禁止检查或导出后代。包含图片边界的祖先节点同样不能整块 design_to_code/get_node_dsl；仅对生成前检查允许的非图片子树生成参考代码。父级浅层查询意外带出图片子树时，在工具编排层或落盘后先裁掉子树，再向模型输出精简结果；不打印、分析或照搬内部代码。
- 用户指定为图片的节点、红框图片区域保持一张图片；不使用组件或样式重画其内部文字和装饰。只导出实际会使用的图片，不递归下载位图容器的 vector/path/mask 碎片。
- 整图导出不等于层级扁平化：保留图片所在父子容器、原始同级顺序、局部坐标及叠放/遮挡/裁切关系。生成上下文的 `tree` 是布局依据，`images` 只是资产索引，不能按图片清单顺序铺成同级元素；也不能把浮在背景图上的独立文字或图片误吞进背景。两个指定图片存在包含关系且导出范围不清楚时，先确认是否重复包含，不擅自合并或拆开。
- 节点默认导出 3x，保存本地资源；临时 URL 不进入业务代码。导出后立即核对实际尺寸和阴影扩边，不凭猜测居中裁切、拉伸或反复调 CSS 位移掩盖资源错误。必要时按准确设计坐标使用同倍率画板裁切，但不得混入相邻文字、图标、背景或遮挡层；无法隔离时保留无修饰占位并报告缺失，不把整卡裁图冒充背景节点。记录来源节点、尺寸、倍率、坐标及裁切方式；素材变化同步更新记录，不能修改设计契约迎合错误资源，也不能通过整体页面截图冒充页面实现。
- 图片意图必须提供页面 selector。用例通过 `intentPlan` 引用生成的计划，`verify` 会自动要求每个 `single-image` selector 只匹配一张图片且没有可见子元素；手写 `structure` 不能削弱这个规则。需要具体配置时参考 [用例](../../cases/intent-items.example.json)。最终只保留使用到的素材。

## 可选本地组件搜索

在编写页面或新建组件前，检查当前工具列表是否提供 `internal-components` 的 `search_internal_component`（工具名可带命名空间前缀）。

- 可调用时，按设计区域的功能搜索，传入目标项目 `projectRoot`，用 `sourceRoots` 限定允许读取的公共组件目录。尊重用户排除的页面或目录；不能安全限定范围时跳过搜索，不通过全项目自动扫描绕过限制。
- 检查候选源码、Props、导出方式及依赖版本，功能和视觉适配时优先复用。无匹配或候选不适配则按项目规范实现，不虚构导入路径或 API。
- **没有发现 MCP、连接/读取失败、工具不可调用、超时或权限不足时直接跳过**，继续生成和验收。简单记录原因，不要求安装或连接 MCP，不反复重试，不将其作为阻塞项。
- 同一需求和源码没有变化时复用搜索结果。图片节点保持图片，不因组件命中改变用户的图片意图。
